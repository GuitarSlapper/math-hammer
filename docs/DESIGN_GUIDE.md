# MathHammer — Android design kit

Пути к изображениям и исходным ресурсам ниже указаны относительно "design-kit/".

## Концепция

Тёмная тактическая эстетика с читаемыми числовыми данными. Не используйте официальные логотипы, фракционные знаки или иллюстрации Games Workshop. Название «MathHammer» — рабочее.

## Цвета (HEX)

| Токен | Значение | Назначение |
|---|---|---|
| `background` | `#111820` | фон приложения |
| `surface` | `#1B2530` | карточки |
| `surfaceBorder` | `#34404C` | границы элементов |
| `gold` | `#C6A76B` | акценты, активные состояния |
| `dangerRed` | `#B84E4B` | обводка результата и ошибки (ошибки можно делать ярче) |
| `textPrimary` | `#F1EEE7` | основной текст |
| `textSecondary` | `#A7AFB7` | подписи |

Контраст текста проверяйте отдельно для мелких подписей и состояния disabled.

## Шрифт

**Exo 2**, автор Natanael Gama, лицензия **SIL Open Font License 1.1**. Кириллица есть.

Официальный каталог: https://fonts.google.com/specimen/Exo+2

Для офлайн-приложения рекомендуем скачать `.ttf` из Google Fonts и включить в `app/src/main/res/font/` вместе с текстом лицензии OFL. Не подключайте шрифт из сети во время работы приложения.

Начертания:
- Regular 400: подписи и значения полей
- SemiBold 600: заголовки секций и управляющие элементы
- Bold 700/800: итоговый урон и числовые результаты

Пример для Jetpack Compose:

```kotlin
val Exo2 = FontFamily(
    Font(R.font.exo2_regular, FontWeight.Normal),
    Font(R.font.exo2_semibold, FontWeight.SemiBold),
    Font(R.font.exo2_bold, FontWeight.Bold)
)
```

## Экран

- Верхняя панель: значок кубика, `MathHammer`, дополнительный подзаголовок.
- Карточка «Атакующий»: `A`, `BS/WS`, `S`, `AP`, `D`.
- Карточка «Защитник»: `T`, `Sv`, `Inv`; `Inv` может быть `Нет`.
- Нижняя область результата: `На 1 атаку` и `Всего` (эквивалент *ожидаемого потенциального урона после сейвов*).
- Подпись под результатом: `Средний потенциальный урон`.
- При недостатке ширины располагайте поля в 2–3 ряда, не сжимайте текст меньше 14 sp.
- Нижняя навигация в концепте декоративна: для MVP можно убрать `Справка/Настройки` ради простоты.

## Размеры (рекомендовано)

- Отступ страницы: 16 dp
- Внутренний отступ карточки: 16 dp
- Вертикальный промежуток карточек: 20 dp
- Минимальная высота области нажатия: 48 dp
- Радиус карточки: 12 dp, поля ввода: 8 dp
- Размер главного результата: 42–50 sp (на компактных экранах уменьшить)

## Данные из макета

Атакующий: A=12, BS=3+, S=8, AP=-2, D=2.
Защитник: T=5, Sv=3+, Inv=4+.

Вероятности: P(hit)=4/6, P(wound)=4/6, P(failed save)=3/6.

Ожидаемый урон на **один кубик атаки**:

`(4/6) * (4/6) * (3/6) * 2 = 0.444444...`

На все 12 атак:

`12 * 0.444444... = 5.333333...`

Показывать `0,44` и `5,33` для русской локали. Не округлять промежуточные значения.

## Что входит

- `references/`: общий концепт и отдельные PNG-референсы блоков интерфейса.
- `icon/mathhammer_icon_generated.png`: иконка, выделенная из арт-концепта.
- `icon/mathhammer_icon_vector.svg`: альтернативная чистая векторная иконка.
- `icon/mathhammer_icon_vector_1024.png`: PNG векторной версии.
- `icon/mathhammer_adaptive_foreground.svg`: вектор для адаптивной иконки Android.
- `android/res/`: готовые заготовки adaptive launcher icon. Перенести в `app/src/main/res/`.
- `ui-icons/`: отдельные простые SVG и PNG для Attack, Defender, Dice, Result.

## Замечание по использованию

Скриншоты и вырезанные PNG — визуальные референсы, не готовые интерактивные элементы. Настоящие поля ввода, переключатель Inv и результаты реализовать нативно на Jetpack Compose. SVG-иконки можно конвертировать в Android Vector Drawable или использовать PNG.

## Обновление v2: сохранённые расчёты и история (офлайн)

**Актуальными считаются макеты из `references_v2/`.** Экраны старого комплекта `references/` сохранены только как исторические референсы. Подробная функциональная спецификация — в [SPECIFICATION.md](SPECIFICATION.md).

### Обновлённая навигация

- Нижняя панель: **«Калькулятор» / «История»**. Дополнительные вкладки «Настройки», «Справка» из концепта не нужны в MVP.
- На экране калькулятора после двух результатов — главная золотая кнопка **«Сохранить расчёт»**. Она активна только при валидных восьми характеристиках.
- В модальном окне вводится **обязательное название 1–80 символов**, например `Accursed Weapon vs Interceptors`. Запись создаётся локально в Room.
- Экран истории показывает **все сохранённые пользователем** записи от последних изменённых к старым: название, дата/время, сводка параметров, оба результата, меню `⋮`.
- Карточка истории открывает расчёт в редакторе; меню — «Переименовать» и «Удалить». Для редактируемого сохранённого расчёта доступны «Сохранить изменения» и «Сохранить как новый».
- Пустое состояние обязательно. После удаления поддержать Undo или диалог подтверждения.

### Новые визуальные компоненты

- `ui-elements-v2/save_button.png` — золотая главная кнопка сохранения.
- `ui-elements-v2/history_item.png` — карточка расчёта с двумя метриками и датой.
- `ui-elements-v2/save_dialog.png` — диалог ввода названия.
- `ui-elements-v2/empty_state.png` — пустая история.

### Шрифты и изображения

Шрифт **Exo 2 / SIL OFL 1.1** (с поддержкой кириллицы), встраивать в APK локально; содержимое архива не включает файлы шрифта. Точные `SVG` и `PNG` макеты сделаны в резервном системном шрифте Noto Sans, поэтому метрики текста при реализации на Exo 2 могут незначительно отличаться.

Файл `references_v2/00_v2_concept_board.png` — атмосферный художественный референс. В нём могут встречаться элементы **за пределами MVP** (избранное, заметки, поиск). Их реализовывать **не нужно**. Источником требований остаётся обновлённое Markdown-ТЗ.

### Состояния, важные для Codex

- Диалог сохранения: пустое имя, валидное имя, название >80 символов, ошибка записи.
- История: пусто / 1 запись / длинный список / длинное название.
- Редактор: новый расчёт / открытая запись / несохранённые изменения / сохранение изменений.
- Сетевая политика: **никакого разрешения `INTERNET` и облачных резервных копий/синхронизации**; данные находятся в приватной базе устройства.
